# Security policy

This is a portfolio and educational prototype. The latest source is the only maintained version; there is no response-time or production-support commitment.

If you discover a vulnerability, use the repository's private vulnerability reporting feature when enabled. Otherwise contact the maintainer through a private channel on their GitHub profile before disclosing exploit details. Never include real credentials, personal data, or customer telemetry in an issue. Public issues are suitable for non-sensitive bugs and documentation improvements.

Reports and workspaces can contain sensitive logs and notes. Keep them out of version control. See `docs/THREAT_MODEL.md` for the trust boundaries and known limitations.
